# 점검 스크립트

Toon & Book Archive(`index.html`)를 고친 뒤 버그가 없는지 확인하는 스크립트다. 앱은 이 폴더를 쓰지 않는다.

## 돌리는 방법

```
tests/run.sh           빠른 점검 (1~2분)
tests/run.sh full      전체 점검: 무작위 9,000번 (5분쯤)
tests/run.sh browser   실제 브라우저로 화면 확인
```

- 처음 돌리면 `tests/node_modules`에 jsdom을 설치한다. Node.js와 Python 3가 필요하다.
- `browser`는 Playwright(Chromium)가 따로 설치돼 있어야 한다. 사진은 `tests/shots/`에 저장된다.
- 마지막 줄에 "모두 통과"가 나오면 된다. 실패하면 어떤 확인이 틀렸는지 나온다.

## 파일

| 파일 | 확인하는 것 |
|---|---|
| `static.py` | 인라인 핸들러가 부르는 함수, `getElementById`로 찾는 id, 중복 함수·id |
| `t_home_plan.js` | 홈의 오늘 계획: 표시, 체크·취소, 숨김, 완독, 삭제된 작품, 날짜 바뀜 |
| `t_fixed_v13.js` | v1.3에서 고친 버그가 다시 생기지 않는지 |
| `t_regress.js` | 체크 취소, 국가 필터, 음수 입력, 예전 데이터, 백업 내보내기·가져오기, 복사 형식 |
| `fuzz_plan.js` | 무작위: 계획을 체크하고 바로 취소하면 체크 전과 완전히 같은지 |
| `fuzz_all.js` | 무작위: 추가·수정·삭제·숨김·회차 탭·계획을 섞어도 오류가 없고 기록이 어긋나지 않는지 |
| `browser_home.js` | 아이폰 크기(390×844) 화면에서 홈 카드를 직접 눌러 보기 |
| `harness.js` | 앱을 jsdom으로 여는 공통 코드. 날짜 고정, 자동저장 확인 |
| `lib.js` | 앱 화면 함수를 불러 작품·계획을 만드는 도우미 |

## 알아둘 것

- **실제 화면 함수를 부른다.** 테스트가 데이터를 직접 만들지 않고 `openAddModal()`, `saveContent()`, `onPlanCheck()` 같은 앱 함수를 그대로 쓴다.
- **자동저장 확인:** 동작 뒤에 메모리 상태, 저장소 내용, 그 저장소로 새로 연 창의 상태가 셋 다 같은지 본다(`consistency`).
- **날짜를 고정한다.** 한국 시간(`TZ=Asia/Seoul`)으로 돌리고, 아침 9시 전 시각도 넣어서 날짜가 하루 밀리는 문제를 잡는다.
- **무작위 점검은 씨앗으로 다시 만들 수 있다.** 실패하면 `seed 12: step 14`처럼 나온다. `node fuzz_plan.js 12 12`로 그 씨앗만 다시 돌린다.
- **고치기 전 버전과 비교:** 점검이 문제를 실제로 잡아내는지 보려면 예전 파일로 돌린다.

  ```
  git show HEAD~1:index.html > /tmp/old.html
  APP_HTML=/tmp/old.html tests/run.sh
  ```

## 확인하지 못하는 것

- 엑셀·PDF 내보내기: CDN 라이브러리(SheetJS, jsPDF)를 빼고 열기 때문에 실행하지 않는다.
- 이미지 내보내기: jsdom에는 캔버스가 없다.
- 아이폰 실제 기기에서만 생기는 문제(확대, 공유 시트, 홈 화면 아이콘).

## 테스트를 추가할 때

- 새 기능은 `t_기능이름.js`를 만들고 `run.sh`에 한 줄 넣는다.
- 고친 버그는 먼저 실패하는 테스트로 재현한 다음 고친다. 고치기 전 파일에서 실패하고 고친 뒤 통과하는지 둘 다 본다.
- 새 동작이 생기면 `fuzz_all.js`의 섞는 동작에도 넣는다.
